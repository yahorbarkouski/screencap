# Screencap security review

Reviewed on 2026-10-15 against commit `284165e` plus the uncommitted edits in the working tree at the time (`ModelClients.swift`, `UnderstandingEngine.swift`, `AppModel.swift`, `AppDatabase.swift`, `Settings.swift`, from another session). Line numbers refer to that working tree; paths are under `Sources/` unless they start with a top-level folder. Two commits landed during the review (`1074e60`, `284165e`) and are included. The untracked agents work (`Sources/ScreencapCore/Agents/`, `plan/05-agents.md`) was not reviewed.

Method: reading the docs and every file under `Sources/`, `scripts/build-app.sh` and `scripts/release.sh`. The only commands run were read-only metadata checks (`stat`, `tmutil isexcluded`, `fdesetup status`, a listing of the cache folder's top level). The app was not run, the live store's contents were not read, and no network request was made.

## Summary

The design is sound for an app of this kind. Data stays local by default; the only network peers are OpenRouter, the user's own bucket and favicon hosts; nothing about the screen is logged; SQL is parameterized; model output never reaches a shell, a file path, a URL or SQL; and the backup uses AES-256-GCM correctly, with each object's name bound as associated data. The two commits that landed during the review closed the file-permission gap and the favicon cookie and cache trail.

The serious problems are in what reaches the models and how the local store is protected. Thread covers send screenshots even in Text-only mode. Private windows are detected by title words that macOS browsers most likely do not show, so "never captured" is unverified. Any process running as the user can copy the plaintext history without a permission prompt. Keys, card numbers and codes visible on screen, including Screencap's own keys during setup, go to OpenRouter unredacted. Nothing lets a remote attacker read the history, so nothing is rated critical.

## What leaves the Mac

Every model request goes to `https://openrouter.ai` over TLS with system trust and no overrides, on an ephemeral session, with the key in `Authorization` and `User-Agent: Screencap/0.1` (`ModelClients.swift:95-124`). "Decider" is `perplexity/pplx-decider-v1.1-27b` on `/api/alpha/decisions`; "writer" is `openai/gpt-6-luna` on `/api/v1/chat/completions`.

| Request | Model | Text | Images (none in Text-only mode, except covers) | When |
|---|---|---|---|---|
| Boundary | Decider | Rule; up to 12 lines of `HH:MM \| app \| title (100) \| host \| new screen text (220)` | The two frames either side, 1024 px JPEG | Each anchor capture, about one a minute |
| Join | Decider | Rule; up to 8 captures per side, `HH:MM:SS \| app \| title (90) \| host \| text (160)` | Last frame before, middle frame after | Each boundary the decider draws |
| Caption and title | Writer | Date, time range, up to 6 captures `app — title (120) — host` with screen text (300) | One frame | Each closed activity |
| Thread | Decider | The activity (screen text 200) and its caption; up to 254 thread cards: name, description, 3 recent captions, up to 5 "Includes" and "Not" corrections | One or two frames | Each closed activity, the open one once, each "Not this thread" |
| Thread card, category | Writer, decider | Last 8 captions; name, description, last 5 captions | None | A thread's 1st, 2nd and every 4th activity, merges, moves |
| Merge | Decider | Pairs of cards (name, description, 4 captions), 128 per request | None | Nightly after 04:00, pairs with a changed card |
| Day headline | Writer | Every session of the day: times, minutes, thread name, longest caption | None | Each day viewed; today at most every 30 minutes |
| Cover | Decider | Thread name and description, app and host per candidate | Up to 5 frames cut to the window, 640 px, also in Text-only mode (H1) | Threads page, first 18 tiles |

Also: favicon `GET https://<host>/favicon.ico` with `User-Agent: Mozilla/5.0` (M1); backup `PUT`, `GET`, `DELETE` and `LIST` to the user's endpoint, which must be HTTPS except on localhost (`Settings.swift:121-130`), signed with SigV4 over the payload hash. No telemetry, crash reporting or update check exists. URL paths are stored locally and never sent; queries and fragments are never stored.

Nothing is written to `/tmp` by the app. The docs put demo stores and page captures there, and copies of the live store that other tools make keep those tools' permissions.

FileVault (on for this Mac) protects the disk while the Mac is off or before login. It does not protect against any process of the logged-in user, an admin using `sudo`, a Time Machine disk without backup encryption, a copy moved to an iCloud-synced folder (M7), or the unified log.

## Done well

- Blocked moments (paused, locked, idle, secure input, excluded app, private title) store only a marker with time and reason, with no title, URL or frame: `Screencap/Platform/CaptureEngine.swift:124-142`, `ScreencapCore/Evidence/CaptureGate.swift:27-37`.
- Excluded apps and Screencap's own windows are cut out of every display's frame by `SCContentFilter`: `Screencap/Platform/ScreenCapturer.swift:39-52`. Secure input stops capture: `CaptureEngine.swift:129`, `CaptureGate.swift:32`.
- No keystroke content is read: input is window-server counters only (`CaptureEngine.swift:215-233`), and the outside-click monitor is mouse-only while the panel shows (`Screencap/UI/Windows.swift:121`).
- Only the host leaves the Mac (`ScreencapCore/Evidence/CaptureText.swift:60,68`); queries and fragments are never stored (`Screencap/Platform/ContextMonitor.swift:78-79`); titles are cut to 90-120 characters and screen text to 160-300 (`CaptureText.swift:41,58,66`; `UnderstandingEngine.swift:319-321,444,522`).
- Text-only mode holds for boundary, join, caption, thread and provisional questions: `UnderstandingEngine.swift:239,327,445,523,579,603`.
- Model output is confined: answers map back to known thread and capture ids (`UnderstandingEngine.swift:527,583,614`; `AppModel.swift:383-384`), the writer uses a strict JSON schema (`ModelClients.swift:256-275`), and output is shown as plain text and never reaches SQL, paths, URLs or processes.
- Network: a fixed HTTPS host for models on an ephemeral session (`ModelClients.swift:95-124`), an ephemeral session for the bucket (`ScreencapCore/Backup/S3Client.swift:112-120`), no trust overrides anywhere, a favicon session with no cookies or cache that skips local hosts and IP addresses (`Screencap/UI/PlaceIcons.swift:60-67,110-116`).
- Backup encryption: CryptoKit AES-256-GCM with random 96-bit nonces and the object name as associated data (`ScreencapCore/Backup/Sealer.swift:15-23`), a key-id check (`Sealer.swift:29-30`), a random 256-bit key (`ScreencapCore/Backup/BackupKey.swift:70`), a Keychain read failure that stops the backup instead of minting a new key (`BackupKey.swift:54-58`, `Screencap/App/BackupDriver.swift:15-16`), and a refusal to mint a key for a bucket that already holds a backup (`BackupKey.swift:69`).
- SigV4 signs the payload hash (`S3Client.swift:20-51`) and was checked against reference signatures from botocore (`SigV4Tests`). Endpoints must be HTTPS except on localhost, and provider endpoints are built from sanitized labels (`ScreencapCore/Support/Settings.swift:106-134`).
- Restore refuses to overwrite a database (`ScreencapCore/Backup/BackupService.swift:188-190`), moves absolute frame paths into the target (`BackupService.swift:226-229`), applies tombstones (`BackupService.swift:207-214`), and updates rows in place with deferred foreign keys (`ScreencapCore/Store/AppDatabase+Backup.swift:225-254`).
- Delete removes frames, thumbnails, search rows, decisions, caption copies in cards and the backup objects, and writes tombstones, in one transaction: `ScreencapCore/Understanding/Corrections.swift:101-139`.
- SQL is parameterized; only constant table names are interpolated, and search queries go through `FTS5Pattern` (`ScreencapCore/Store/AppDatabase+Captures.swift:117`). No log line carries a title, URL or screen text.
- Files are 0600 and folders 0700 (`Screencap/App/main.swift:19`, `ScreencapCore/Support/StoreLocation.swift:36-38`). Keychain items are not synchronizable (`ScreencapCore/Support/Keychain.swift:64`); keys are typed into secure fields and cleared after saving (`Screencap/UI/SettingsView.swift:39-45`); the recovery key is never drawn on screen.
- Signing: hardened runtime on the app and the helper with no entitlements, so no JIT, unsigned-memory, library-validation or `get-task-allow` exceptions, and a strict verify (`scripts/build-app.sh:46-48`). Releases use a secure timestamp, notarization and stapling, refuse uncommitted sources and publish checksums (`scripts/release.sh:22-25,39-49`). GRDB is pinned to an exact version and revision (`Package.swift:12`, `Package.resolved`).
- The OCR helper is a child process on pipes with no listening endpoint, and results are matched by capture id (`ScreencapCore/Evidence/OCRRunner.swift:46-54`). The test bucket listens on 127.0.0.1 only (`scripts/fake-s3.py:94`).

## Not verified

- What macOS Safari, Chrome, Arc, Dia, Brave, Edge and Firefox put in private windows' titles (H2), and what ScreenCaptureKit returns while the session is locked (L1).
- Whether OpenRouter offers ZDR endpoints for both models on these endpoints (M4), and the exact shape of its moderation errors (L4).
- Whether `SCShareableContent.applications` lists apps with no on-screen window (L6), and whether `sharingType = .none` still hides windows from ScreenCaptureKit on macOS 26 (L9).
- The H4 onboarding scenario follows from the code; it was not reproduced. A pre-publication sweep of tracked research files for real captures was not done; spot checks of `research/understanding-probes/` found only synthetic images and structural results.
- The agents work in progress: its gate (`agents.isEnabled`) would live in user defaults, which any process of the user can change with `defaults write`, and agents reading screen text inherit H4's secrets and M2's injection risk.
